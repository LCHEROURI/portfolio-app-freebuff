## Minor

### 🟡 Email headings lose the exact model id, unlike the UI badge, `lib/openrouter.ts:400,412`
**Problem**: `withExecutiveSummary` and `withTopThreeNarration` now render only the friendly label (e.g. "DeepSeek Chat") in the emailed section heading. The UI badge keeps the raw id available as a hover tooltip, but a rendered email has no hover, so a reader of the daily/weekly report cannot recover the exact model id that wrote the summary.
**Why it matters**: this app's core purpose is tracking and comparing models; the emailed report is the persistent record. Losing the precise id in the only human-readable surface makes the A/B trail harder to audit from the inbox.
**Suggested fix**: keep the friendly label in the heading, but append the raw id once (e.g. a small footer line "Model: deepseek/deepseek-chat", or an HTML title attribute on the heading) so the email stays fully traceable. The report JSON's aiModel field already keeps the raw id, so this is a presentation-level addition only.
