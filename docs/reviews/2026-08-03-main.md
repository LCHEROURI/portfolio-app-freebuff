## Minor
### 🟡 Env line text still lives in three places, `lib/integrationVarLinks.ts` and `app/integrations/page.tsx`
**Problem**: The stated goal of the final change was to stop the URL sets from drifting, and the footer link now derives from the per var map. But the .env.example line text still exists in `VAR_ENV_LINES` inside `lib/integrationVarLinks.ts`, again in the `SETUP_GUIDES` code blocks inside `app/integrations/page.tsx`, and again in the repo .env.example.
**Why it matters**: If someone edits a line like `SUPABASE_URL=https://...` in one place but not the others, the copy button and the checklist step will disagree with each other and with the real .env.example.
**Suggested fix**: Derive the `SETUP_GUIDES` code blocks from `varEnvLine` (or one shared source for the line text) so the copy buttons and the step blocks emit exactly the same string.

### 🟡 The riskiest hook logic is untested, `lib/useIntegrationStatus.ts`
**Problem**: `lib/integrationDiff.ts`, `lib/integrationVarLinks.ts`, and the link component all have tests, but the hook logic in `lib/useIntegrationStatus.ts` has none: the union `prev.filter(...)` reordering, the TTL re arm behavior, and the no badge on first load rule.
**Why it matters**: That is the part of the feature most likely to regress, and it is the only piece without a safety net.
**Suggested fix**: Extract the union into a pure function and test it, or add a small hook level test with a mocked fetch.
